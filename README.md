# Кофейный проект — Форма заявок с интеграцией Telegram API


## Как запустить проект локально

[Versel](https://kvarta-ecru.vercel.app/index.html)


Проект представляет собой лендинг кофейни с интерактивной формой заказа. В рамках тестового задания была реализована полноценная клиент-серверная архитектура с валидацией данных, защитой от спама и безопасной отправкой уведомлений в Telegram.

## Стек технологий
* **Frontend:** HTML5, CSS3 (адаптивная верстка, кастомные свойства, сетки Grid/Flexbox), JavaScript (Vanilla JS).
* **Backend:** Node.js, Express.js (обработка POST-запросов, проксирование в Telegram API).
* **Безопасность:** Библиотека `dotenv` для скрытия ключей, модуль `cors` для контроля доступа.
* **Инструменты разработки:** ИИ-ассистент (Claude/ChatGPT).

## Отчёт о разработке (README для ревью)

### 1. Что делалось самостоятельно, а что с помощью ИИ
* **Самостоятельно:** Разработка концепции, визуальный стиль, вся CSS-верстка (включая кастомные кофейные оттенки, плашки, сетку товаров и позиционирование элементов), структура HTML-документа, логика появления/скрытия дополнительных полей ввода (комментарии) и верстка модального окна успеха. Также **самостоятельно с нуля создала и настроила Telegram-бота** через `@BotFather`, получила токен и определила актуальный `CHAT_ID` своего аккаунта для дублирования заявок с сайта напрямую на телефон.
* **С помощью ИИ:** Проектирование бэкенда на Express.js, написание регулярного выражения для строгой проверки белорусских номеров телефонов, реализация 10-минутного таймера ограничения повторной отправки формы (cooldown) с использованием `localStorage` и вывод обратного отсчета прямо на кнопку «Отправить». Также с помощью ИИ **провела развертывание (деплой) проекта на удаленный хостинг**, чтобы API работало в облаке «живьем», а форма стабильно отправляла сообщения боту из любого места, а не только с локального компьютера (`localhost`).

### 2. Ошибки ИИ и как они были замечены
В процессе совместной разработки ИИ допустил несколько критических логических и синтаксических ошибок, которые пришлось локализовать и исправлять вручную через отладку:
1. **Синтаксические опечатки в fetch:** ИИ несколько раз некорректно генерировал URL-адрес запроса к Telegram API внутри шаблонных строк JavaScript — терял знак `$` перед фигурной скобкой переменных (`{TELEGRAM_BOT_TOKEN}`), путал слэши или забывал поддомен `api.` (писал `telegram.org` вместо `api.telegram.org`). Ошибка была замечена по «тишине» в консоли браузера и в ходе анализа вкладки Network (запросы улетали на несуществующие хосты).
2. **Проблема кодировки и длины строки (Content-Length):** При переносе логики на Node.js ИИ настроил отправку заголовка `'Content-Length': data.length`. В результате сообщения, содержащие только английский текст или цифры, доходили, но как только отправлялся кириллический комментарий, Telegram молча отбрасывал запросы, хотя возвращал статус `200`. Ошибка была локализована через логирование сервера: выяснилось, что `data.length` считает количество *символов*, тогда как кириллица занимает по **2 байта** на символ. Проблема была решена ручной заменой на системный метод `Buffer.byteLength(data)`.
3. **Зависание интерфейса при обрыве сети:** ИИ не предусмотрел таймаут запроса, из-за чего при блокировках связи (например, под VPN или AdBlock) кнопка формы бесконечно оставалась в заблокированном («негативном») состоянии. В код фронтенда был принудительно внедрен `AbortController`, сбрасывающий ожидание через 4 секунды с выводом понятной ошибки пользователю под кнопкой.
4. **Фальшивые уведомления об успешной отправке (Логическая ошибка):** ИИ изначально написал код бэкенда и фронтенда так, что модальное окно «Отлично! Ваша заявка принята» открывалось пользователю в любом случае — даже если бэкенд упал с сетевой ошибкой или отвалилось соединение с интернетом. Я заметила эту проблему при детальном просмотре логики обработки промисов (`.catch`). Если бы сервер Telegram заблокировал запрос, пользователь сайта думал бы, что заявка отправлена, а менеджер кофейни её бы не получил. **Я полностью переписала этот блок:** теперь при сбое сети окно успеха блокируется, форма не очищается, кнопка «Отправить» возвращается в активное состояние, а под ней динамически выводится понятный кофейно-красный текст ошибки, чтобы пользователь знал, что отправка не удалась, и мог повторить попытку.

### 3. Что не успела или сделала бы иначе при наличии времени
* **Переход на Next.js:** Поскольку в требованиях указано, что Next.js является основным стеком компании, в реальной продуктовой разработке я бы сразу развернула проект на Next.js. Это позволило бы избавиться от необходимости держать отдельный сервер `server.js`, так как бэкенд-эндпоинт `/api/lead` можно было бы элегантно реализовать через встроенные **Route Handlers (Serverless-функции)** в папке `app/api/`.
* **База данных:** На текущий момент заявки идут транзитом сразу в Telegram. Правильнее было бы подключить легковесную базу данных (например, PostgreSQL через Prisma или MongoDB), чтобы сохранять лиды на сервере на случай сбоев в работе мессенджера.
